# LiteFilm 0.1.0 (7): retain page curl, contain its rendering

## Requirement and change

The user rejected replacing vertical page curl with slide/fade. Restore native upward/downward page curl while preventing extra colored areas outside the photo. Horizontal flips and Reduce Motion remain unchanged.

Reproduced the original full-preview curl with a deterministic Debug probe. At the midpoint, the landscape image's upper letterboxing became a large cyan rectangle and the curl shadow extended below/left of the photo. The production fix uses a transparent, clipped host sized to the actual aspect-fit image rectangle, with a temporary image view for the native curl. The outgoing image must be committed for one display interval before starting the curl; starting it in the insertion transaction did not visibly animate.

Completion, interruption, new swaps, layout changes and view dismantling remove the temporary hierarchy. The latest target image remains underneath. A completion token prevents an old transition callback from clearing a newer page.

## Verification

- Debug arm64 simulator and signed Release device builds passed. Version verified as 0.1.0 (7).
- Real simulator compositor screenshots inspected at upward quarter, midpoint and three-quarter checkpoints; downward midpoint; portrait midpoint; transparent-border midpoint. Curled page geometry is visible and contained in the image rectangle.
- Boundary analysis of the captured JPEGs, allowing 2 pixels at the photo edge and 16/255 channel deviation for JPEG ringing: legacy midpoint had 42,833 unexpected pixels outside the photo; all six fixed checkpoints had zero. This is evidence for these captured cases, not a guarantee for every image/device.
- Debug lifecycle checks passed: curl is retained; landscape letterboxing is excluded; gesture interruption preserves the latest image and removes the curl; resize clears temporary layers and settling state; rapid swaps keep only one temporary page; completion removes all temporary content; Reduce Motion skips curl.
- Lifecycle runner has a 30-second timeout and 96-thread ceiling. Sampled app peak was 19 threads. The simulator emitted a pre-existing Apple accessibility duplicate-class warning but completed all checks.
- Auditing the watchdog revealed that macOS `ps -M` continuation rows omit USER, moving PID to the first whitespace-delimited field. Corrected both the new lifecycle runner and existing encoder runner to count those rows. Encoder regression rerun passed: compiler peak 8 threads, test peak 5 threads. Previous reports of a one-thread peak were undercounts, not valid measurements of the whole process.
- Project plist lint and Git whitespace checks passed. Debug probe markers are absent from the Release executable.
- Signed build 7 installed and launched on the paired iPhone without uninstalling or erasing app data.

The phone UI automation runner is offline, so physical-device gesture appearance has not been independently captured. Visual verification above used the iOS 26.5 simulator. No App Store submission was withdrawn or replaced.

## Reproduction

Install a Debug simulator build, then run:

```sh
python3 Scripts/test_preview_curl.py --device <dedicated-booted-simulator-UDID> --output <external-log-path>
```

For visual inspection launch with `--preview-transition-probe --probe-progress=0.5`. Optional flags: `--probe-down`, `--probe-portrait`, `--probe-alpha`. The Debug-only `--probe-legacy` flag reproduces the original full-bounds curl. The probe slows/pauses the compositor and holds its temporary page for inspection; lifecycle checks use normal production timing and cleanup. Release builds exclude the probe.
